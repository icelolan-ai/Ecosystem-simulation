# LIVING TERRARIUM 🌿

ระบบนิเวศจำลอง 3 มิติบนเกาะเปิด สร้างด้วย Three.js — หมุนดู ซูมเข้าไปใกล้ ๆ ปลูกพืช ปล่อยสัตว์ เรียกฝน
แล้วเฝ้าดูว่าประชากรจะแกว่งไปทางไหน

> **ระบบนิเวศจำลองแบบง่าย** — ตั้งใจให้เห็นภาพความสัมพันธ์ระหว่างน้ำ พืช สัตว์กินพืช และผู้ล่า
> ในเวลาไม่กี่นาที ไม่ใช่แบบจำลองทางชีววิทยาที่แม่นยำ

## โลกของมัน

เกาะกลมรัศมี 18 หน่วย (พื้นที่ราว 1,018 หน่วย²) มีแอ่งน้ำอยู่ค่อนไปทางหนึ่ง
ไม่มีภาชนะครอบ กล้องจึงซูมเข้าไปเดินดูใต้ทรงพุ่มได้จนถึงระยะ 2.5 หน่วย
และถอยออกมาดูทั้งเกาะได้ที่ 140 หน่วย

`WORLD.radius` เป็นปุ่มเดียวของขนาดโลก — ความละเอียดกริด ขนาดแอ่งน้ำ เพดานจำนวน
และจำนวนสิ่งมีชีวิตเริ่มต้น คำนวณจากมันทั้งหมด (เพดานคิดเป็นความหนาแน่นต่อพื้นที่)
อยากได้เกาะใหญ่หรือเล็กกว่านี้ก็แก้ค่าเดียว แล้ว**รัน `node tools/balance-test.mjs` ใหม่**

## เปิดใช้งาน

ไม่ต้อง build ไม่ต้องติดตั้งอะไร เพราะ Three.js ถูก vendor ไว้ใน `js/vendor/` แล้ว
ต้องเสิร์ฟผ่าน HTTP (ES modules ใช้ `file://` ไม่ได้):

```bash
python3 -m http.server 8000
# เปิด http://localhost:8000
```

### Deploy

มี GitHub Actions workflow (`.github/workflows/pages.yml`) ที่ deploy ขึ้น GitHub Pages
อัตโนมัติทุกครั้งที่ push เข้า `main` และรัน `tools/balance-test.mjs` ตรวจซิมูเลชันก่อน deploy
(บน pull request จะรันเฉพาะขั้นตรวจ ไม่ deploy)

ตั้งค่าครั้งเดียวก่อนใช้: **Settings → Pages → Source: "GitHub Actions"**

## สิ่งที่ระบบทำ

### สิ่งมีชีวิตมี state จริง

ทุกตัวเก็บสถานะของตัวเองและตัดสินใจจากสถานะนั้นทุก step:

| | พลังงาน | อายุ | ความหิว | เป้าหมาย |
|---|---|---|---|---|
| **ต้นไม้ใหญ่** | ทรงพุ่ม โตช้ากว่าพืชเล็กมาก | อายุยืนกว่าราว 10 เท่า | — | อยู่กับที่ |
| **พืช** | ขนาด/ชีวมวล โตตามความชื้นและธาตุอาหาร | ตายเมื่อหมดอายุขัย | — | อยู่กับที่ |
| **สัตว์กินพืช** | กินพืชเพื่อเติม ใช้ตลอดเวลา | แก่แล้วตาย | ยิ่งหิวยิ่งกล้าเสี่ยง | พืชที่เล็ง / จุดที่เดินไป / ทิศหนี |
| **ผู้ล่า** | ได้จากการล่าสำเร็จ | แก่แล้วตาย | หิวแล้วถึงออกล่า | เหยื่อที่ไล่ / จุดลาดตระเวนในอาณาเขต |
| **ผู้ย่อยสลาย** | ได้จากการย่อยซากในบริเวณนั้น | แก่แล้วตาย | ไม่มีซากก็ฝ่อ | อยู่กับที่ |

นอกจากนี้สัตว์ทุกตัวยังมี **ยีนความเร็ว** ที่สืบทอดถึงลูก (ดูหัวข้อวิวัฒนาการ)

การกิน การสืบพันธุ์ และการตาย มีผลต่อจำนวนประชากรจริง ๆ ไม่ได้สคริปต์ไว้
กราฟประชากรอ่านจาก `sim.history` ที่บันทึกจากซิมูเลชันโดยตรงทุก 1 วินาทีจำลอง

### วัฏจักรสารอาหาร

ความตายไม่ใช่ทางตัน — สารอาหารหมุนกลับเป็นวง:

```
พืชและต้นไม้ดูดธาตุอาหารจากดินเพื่อโต
   -> ต้นไม้ทิ้งใบลงดินตลอดเวลา (ทางป้อนซากที่ไม่ต้องรอให้ใครตาย)
   -> สัตว์กินพืช แล้วคืนสารอาหารส่วนใหญ่ลงดินเป็นมูล
   -> ซากพืช ซากสัตว์ และมูล กลายเป็นซากอินทรีย์ในดิน
   -> เห็ดราขึ้นบนซาก ย่อย แล้วปล่อยธาตุอาหารกลับลงดินจุดนั้น
   -> พืชใช้ต่อ
```

พืชโตได้เท่าที่ดินมีให้ (จำกัดด้วยทั้งความชื้น **และ** ธาตุอาหาร) ถ้าวงจรย่อยสลายหยุด
ดินจะจืดลงและพืชจะโตไม่ขึ้น จำนวนเห็ดราจึงเป็นตัวบอกว่าเพิ่งมีความตายมากแค่ไหน —
ลองดู preset "ผู้ล่ามากเกินไป" จะเห็นเห็ดราพุ่งขึ้นทันทีหลังเหยื่อถูกล่าเกลี้ยง

มีการย่อยสลายตามธรรมชาติแบบช้ามากรองรับไว้ และสปอร์ลอยในอากาศทำให้เห็ดรากลับมาได้
แม้เคยหายไปหมด ระบบจึงไม่ตายถาวรเพราะผู้ย่อยสลายสูญพันธุ์

### วิวัฒนาการ

สัตว์มียีนความเร็วที่**สืบทอดถึงลูกพร้อมกลายพันธุ์เล็กน้อย** และความเร็วมีต้นทุน:
ตัวที่เร็วกว่าเปลืองพลังงานตามกำลังสอง ทั้งตอนวิ่งและตอนอยู่เฉย (กล้ามเนื้อมากก็กินมาก)

จุดเหมาะสมจึงขยับตามแรงกดดันจริง ไม่ใช่ไต่ขึ้นเรื่อย ๆ อย่างไร้จุดจบ:

| สถานการณ์ | ทิศทางของยีน (วัดจากหลาย seed) |
|---|---|
| ผู้ล่าเยอะ (preset ผู้ล่ามากเกินไป) | **+0.041** — เร็วขึ้น เพราะหนีรอดสำคัญกว่า |
| ไม่มีผู้ล่าเลย (การทดลองควบคุม) | **−0.018** — ช้าลง เพราะความเร็วเป็นภาระเปล่า |

ดูได้จากแถบ "ยีนความเร็วเหยื่อ" ในกราฟ และคลิกสัตว์ตัวใดก็ได้เพื่อเทียบยีนของมันกับค่าเฉลี่ยของฝูง

### ฤดูกาล

1 ปี = 6 นาทีจำลอง แบ่งเป็น ฤดูฝน → ปลายฝน → ฤดูแล้ง → ต้นฝน
ฤดูแล้งระเหยเร็วขึ้น ฤดูฝนมีฝนปรอยตกเองเป็นระยะ (เบากว่าปุ่ม "เรียกฝน" ที่ผู้ใช้กด)

ที่น่าสนใจคือ**ฝนตามฤดูกลายเป็นตัวช่วยเสถียรภาพที่แรงที่สุดในระบบ** — วัดจาก seed
ที่ไม่ได้ใช้จูน:

| การตั้งค่า | อยู่รอด 15 นาที |
|---|---|
| ไม่มีฤดูกาลเลย | 54% |
| มีฤดูกาล แต่ไม่มีฝนตามฤดู | 20% |
| มีฤดูกาล + ฝนปรอยตามฤดู | **75%** |

ฤดูแล้งอย่างเดียวคือยาพิษ แต่พอมีฝนมาเป็นจังหวะ มันกลับกันฐานพืชไม่ให้ล่มตอนเหยื่อบูม

> ตัวเลขสามบรรทัดนี้วัดไว้ตอนแผนที่ยังเป็นรัศมี 9 (ก่อนขยายเกาะและก่อนมีต้นไม้ใหญ่)
> ยังไม่ได้วัดซ้ำบนแผนที่ปัจจุบัน ทิศทางน่าจะเหมือนเดิม แต่ตัวเลขจริงคงไม่ตรงแล้ว

### วงจรที่ทำให้ระบบอยู่ได้นาน

กลไกที่ป้อนกลับกันเองเพื่อกันระบบล่ม:

1. **วัฏจักรน้ำของเกาะ** — แอ่งน้ำซึมออกไปตามดิน น้ำระเหยตามความชื้นที่มี
   แล้วกลั่นกลับลงดินเป็นน้ำค้าง ทำให้เกิดความชื้นไล่ระดับจากแอ่งน้ำออกไป
2. **สัตว์กินพืชเล็มไม่ถอนราก** — หยุดกินเมื่อพืชเหลือขนาดหนึ่ง พืชจึงงอกกลับได้
3. **การซุ่มโจมตี** — สัตว์กินพืชที่ตื่นตัววิ่งเร็วกว่าผู้ล่า ผู้ล่าจึงจับได้เฉพาะตอนเหยื่อ
   เผลอก้มกินหญ้า (มีเวลาตอบสนองหน่วงอยู่) และไล่ได้จำกัดเวลาก่อนหมดแรง
4. **ทรงพุ่มของต้นไม้ใหญ่เป็นที่กำบังที่ไม่หายไปตอนวิกฤต** — พุ่มไม้เล็กหายไปพร้อมพืช
   ตอนเหยื่อบูมแล้วเล็มเกลี้ยง แต่ต้นไม้โตช้าและถูกกินไม่ได้ ที่กำบังใต้ทรงพุ่มจึงยังอยู่
   วัดได้ว่าตอนพื้นโล่งเหลือที่กำบัง ~0.2 ใต้ทรงพุ่มยังอยู่ที่ ~0.9
   (ตั้ง `TREE.coverWeight = 0` แล้วค่านี้ตกลงไปเท่าพื้นโล่งทันที — เทสต์ข้อ
   `tree canopy is real cover` คอยกัน)
5. **พุ่มไม้เป็นที่กำบัง** — ยิ่งพืชรก ผู้ล่ายิ่งมองเห็นเหยื่อยาก
   เหยื่อน้อย → พืชฟื้น → กำบังดีขึ้น → เหยื่อรอด เป็นวงป้อนกลับที่กันระบบล่ม
6. **ผู้ล่าหวงอาณาเขต** — ลูกผู้ล่าเกิดได้ต่อเมื่อยังมีพื้นที่ว่างห่างจากอาณาเขตตัวอื่น
   จำนวนผู้ล่าจึงถูกคุมด้วยพื้นที่ ไม่ใช่ด้วยเพดานตัวเลข
7. **สืบพันธุ์ตามทรัพยากรรอบตัว** — สัตว์กินพืชออกลูกเมื่อบริเวณนั้นยังมีพืชพอ
   ผู้ล่าออกลูกเมื่อมีเหยื่อในระยะ

**เพดานจำนวน** (`CAPS`) — เอกสารรุ่นก่อนเขียนว่า "มีไว้คุม performance เท่านั้น"
ซึ่ง**ไม่ตรงกับความจริงที่วัดได้** ตอนประชากรบูม เพดานจะตัดยอดของการบูม
และการตัดยอดนั้นช่วยพยุงระบบจริง (ทดลองยกเพดานขึ้นแล้วอัตราการอยู่รอดตกลง
เพราะ overshoot แรงขึ้นจนล่มหนักกว่าเดิม)

พูดให้ตรงคือ เพดานทำสองหน้าที่: คุมต้นทุนการเรนเดอร์ **และ** เป็นตัวหน่วงการบูม
ประชากรแตะเพดานเป็นช่วง ๆ ในระหว่างบูม แต่ไม่ได้นอนค้างอยู่ที่นั่นตลอดเวลา
(เทสต์มีข้อ `saturation` คอยกันกรณีหลัง)

### ระบบอยู่รอดได้นานแค่ไหน

- **seed ที่แถมมากับ preset** ถูกเลือกมาให้อยู่รอดและแกว่งสวยเกิน 15 นาที
- **seed ทั่วไปที่ไม่ได้คัดมา** อยู่รอดครบ 15 นาที **25 จาก 48 seed (52%)**
  ที่เหลือจบด้วยการล่มของวัฏจักรล่า–เหยื่อ ซึ่งเป็นผลลัพธ์ตามธรรมชาติของระบบ ไม่ได้กันไว้

| ชุด seed | อยู่รอด 15 นาที |
|---|---|
| ชุดที่เทสต์ใช้ (`s0`–`s23`) | 14/24 (58%) |
| ชุดที่ไม่เคยใช้จูนเลย | 11/24 (46%) |
| **รวม 48 seed** | **25/48 (52%)** |

ช่องว่าง 12 จุดเปอร์เซ็นต์ระหว่างสองชุดคือขนาดของ over-fitting ที่เหลืออยู่ —
เลขที่ควรอ้างถึงคือ 52% ไม่ใช่ 58%

> ตัวเลขนี้ต่ำกว่า ~75% ที่เคยวัดไว้ตอนแผนที่รัศมี 9 เพราะแผนที่ใหญ่ขึ้นสี่เท่า
> ทำให้การบูมของประชากรแรงขึ้นตามพื้นที่ แล้วล่มหนักกว่าเดิม (เพดานสูงขึ้นตามพื้นที่ด้วย)
> เป็นการแลกที่ตั้งใจ: ได้แผนที่ให้เดินสำรวจ แลกกับความเปราะที่มากขึ้น
> เกณฑ์ของเทสต์จึงตั้งไว้ที่ 8/24 ไม่ใช่ค่าที่วัดได้ตอนนี้ จะได้ไม่พังทุกครั้งที่แกว่งตามปกติ

> เอกสารรุ่นก่อนเคยเขียนว่า "7 จาก 8 seed" ซึ่งมาจากกลุ่มตัวอย่างเล็กที่บังเอิญดี จึงสูงเกินจริง

### แชร์การทดลอง

เพราะระบบเป็น deterministic ลิงก์จึงไม่ต้องเก็บสถานะของสิ่งมีชีวิตทีละตัว
เก็บแค่ **preset + seed + ลำดับการกระทำพร้อม step ที่เกิด** ก็พอ:

```
#p=balanced&s=mossgarden&a=331r!331h!331x!331g@0.1,0.1
     preset      seed      ฝน  +เหยื่อ +ผู้ล่า  ปลูกพืชที่ (0.1, 0.1)
```

เปิดลิงก์แล้วการกระทำจะถูกเล่นซ้ำ ณ step เดิมเป๊ะ ทดสอบแล้วว่าสถานะปลายทางตรงกัน
ทุกค่า รวมถึงยีนเฉลี่ยและความชื้นถึงทศนิยม 5 ตำแหน่ง

> รายละเอียดที่ต้องระวัง: พิกัดที่ปลูกถูก**ปัดเศษตั้งแต่ตอนปลูก** ให้เท่ากับความละเอียด
> ที่ URL เก็บได้ ถ้าไม่ทำ ความต่างระดับ 0.05 หน่วยจะถูกความอลวนขยายจนผลลัพธ์แยกกัน
> ภายในสองนาที

### ทำซ้ำได้

- **fixed timestep** — เดินซิมูเลชันทีละ 1/30 วินาทีจำลองเสมอ ความเร็วเวลาเปลี่ยนแค่จำนวน step ต่อเฟรม
  ผลลัพธ์จึงไม่ขึ้นกับ framerate ของเครื่อง
- **seeded randomness** — ค่าสุ่มทุกค่ามาจาก mulberry32 ที่ seed ได้ (พิมพ์เป็นคำก็ได้)
  seed เดิม + ลำดับการกระทำเดิม = ผลลัพธ์เดิมทุกครั้ง

| ปลูกต้นไม้ใหญ่ | กด **ปลูกต้นไม้** แล้วคลิกบนผิวดิน — จะได้ต้นกล้าที่ต้องรอโต |
| เพิ่มสัตว์ | ปุ่มเพิ่มสัตว์กินพืช / เพิ่มผู้ล่า |
| เรียกฝน | ปุ่มเรียกฝน (`F`) |
| แชร์การทดลอง | ปุ่ม **คัดลอกลิงก์การทดลอง** — ใครเปิดลิงก์จะได้เทอราเรียมใบเดียวกันเป๊ะ |
| หยุด / เดินต่อ | `Space` |
| เดินทีละก้าว | ปุ่ม **ทีละก้าว** (เดินครั้งละ 1 วินาทีจำลอง) |
| ปรับความเร็ว | สไลเดอร์ 0.25× – 8× |
| เริ่มใหม่ | ปุ่ม **เริ่มใหม่** (`R`) — ใช้ seed เดิม |
| เปลี่ยน preset | ปุ่มรูปแบบเริ่มต้น หรือ `1` `2` `3` |

### Preset

| รูปแบบ | เรื่องราวที่จะได้เห็น |
|---|---|
| **สมดุล** | ประชากรแกว่งเป็นวัฏจักรล่า–เหยื่อซ้ำ ๆ ได้นานหลายนาที |
| **ภัยแล้ง** | ดินแห้งลงเรื่อย ๆ พืชหด สัตว์ค่อย ๆ ร่วง — กดเรียกฝนเป็นระยะจะยื้อไว้ได้ |
| **ผู้ล่ามากเกินไป** | เหยื่อถูกล่าจนเกือบหมดใน 1 นาที ผู้ล่าอดตายตาม แล้วเหยื่อที่เหลือรอดจะฟื้นกลับมา |

## โครงสร้างโค้ด

```
index.html          โครงหน้าและแผงควบคุม
css/style.css       ธีมโทนอบอุ่น + responsive
js/config.js        ค่าคงที่ พารามิเตอร์สิ่งมีชีวิต และ preset ทั้งหมด
js/rng.js           seeded PRNG (mulberry32)
js/simulation.js    แกนระบบนิเวศ — ไม่พึ่ง DOM/Three.js จึงรันทดสอบใน Node ได้
                    (ความชื้น ธาตุอาหาร ซากอินทรีย์ ที่กำบัง และสิ่งมีชีวิต 5 กลุ่ม)
js/scene.js         ฉาก 3 มิติ, InstancedMesh, การเลือก, ฝน, วงจรกลางวัน–กลางคืน
js/chart.js         กราฟประชากรย้อนหลัง (Canvas 2D)
js/ui.js            แผงควบคุมและการ์ดข้อมูลสิ่งมีชีวิตที่เลือก
js/main.js          ลูปหลัก fixed timestep + การผูกอินพุต
js/vendor/          Three.js r169 + OrbitControls + BufferGeometryUtils + RoomEnvironment
tools/balance-test.mjs  ทดสอบสมดุลแบบ headless
```

`simulation.js` ไม่ import อะไรจาก Three.js หรือ DOM เลย ทดสอบสมดุลจึงรันตรง ๆ ได้:

```bash
node tools/balance-test.mjs           # ตรวจทั้งหมด (CI ใช้อันนี้ ~25 วินาที)
node tools/balance-test.mjs --trace   # พิมพ์เส้นทางประชากรของทั้ง 3 preset ด้วย
```

สคริปต์นี้ **exit 1 เมื่อไม่ผ่าน** และตรวจ:

| ข้อ | ตรวจอะไร |
|---|---|
| determinism | seed เดิมสองรันต้องได้สถานะเหมือนกันทุกตัว |
| survival | seed กลาง ๆ ต้องรอด 15 นาทีอย่างน้อย 8/24 |
| preset seed | seed ที่ผู้ใช้เห็นตอนเปิดเว็บต้องรอดจริง |
| decomposers | วงจรย่อยสลายต้องหมุนจริง ไม่ใช่ของประดับ |
| soil | ธาตุอาหารในดินต้องไม่ไหลลงจนหมด |
| headroom | ประชากรเฉลี่ยต้องต่ำกว่า 90% ของเพดาน |
| presets | ทุก preset ต้องเดินได้โดยไม่ error |

> ค่าสมดุลถูกจูนมาอย่างละเอียด การแก้ตัวเลขใน `config.js` เพียงเล็กน้อยก็ทำให้ระบบล่มได้
> **รันเทสต์ทุกครั้งหลังแก้** — เทสต์รุ่นแรกพิมพ์ผลอย่างเดียวแล้ว exit 0 เสมอ
> ทำให้ CI จับ regression ไม่ได้เลย ตอนนี้แก้แล้ว

## เรื่อง performance

- สิ่งมีชีวิตทุกชนิดวาดด้วย `InstancedMesh` ชนิดละ 1 draw call (ปรับ `.count` ตามจำนวนที่มีชีวิตอยู่)
- ตารางความชื้น / ธาตุอาหาร / ซากอินทรีย์ ขนาด 32×32 และตารางที่กำบัง 12×12
  (ตารางที่กำบังอัปเดตทุก 0.5 วินาทีจำลอง ไม่ใช่ทุก step)
- แก้วใช้วัสดุโปร่งใสแบบ stylized + ขอบ Fresnel แทน `transmission` เพื่อเลี่ยง render pass เพิ่ม
- สีผิวดินอัปเดตตามความชื้นจริงที่ ~3 ครั้ง/วินาที ไม่ใช่ทุกเฟรม
